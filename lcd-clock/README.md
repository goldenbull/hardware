# 关键词训练数据采集

Waveshare **ESP32-C5-Touch-LCD-3.5** 上的录音工具：用**板载麦克风**把"打开屏幕""关闭屏幕"
录成长 WAV 存到 TF 卡，再拿到 Mac 上切片、训练离线关键词模型。

训练数据必须用同一块板子、同一个麦克风、同一套参数来录：模型在板子上要听的就是
这条链路的声音，用手机或电脑麦克风录的数据和它的频响、底噪、增益都不一样。
采集链路集中在 `main/mic.c`，以后识别固件原样复用这个文件。

## 界面

| 区域 | 内容 |
| --- | --- |
| 顶部 | TF 卡剩余空间 |
| 提示卡片 | 录音中显示"请说 **打开屏幕**"，边框变红；空闲时显示"空闲" |
| 中部 | 本次录音时长、文件名、削顶 / 丢帧计数 |
| 电平条 | 麦克风实时峰值，**空闲时也在动**，开录之前可以先试音 |
| 按钮 | **开始录音1**（打开屏幕）、**开始录音2**（关闭屏幕）、**结束录音** |

录音中两个开始按钮会变灰，只有"结束录音"能点。

## 录到卡上的文件

```
/sdcard/kws/open_001.wav     开始录音1，每按一次编号 +1，永不覆盖
/sdcard/kws/open_002.wav
/sdcard/kws/close_001.wav    开始录音2
/sdcard/kws/sessions.csv     每次录音一行
```

- WAV：16kHz / 16bit / 单声道 PCM，从按下开始到按下结束是一整段连续录音
- 每 5 秒回写一次文件头并 fsync，录到一半断电，最多丢最后 5 秒，文件仍能正常打开
- `sessions.csv` 各列：`file, keyword, duration_s, samples, dropped_samples, clipped_samples, gain_db, sample_rate, wall_ms`。
  `dropped_samples` 正常应为 0；`wall_ms` 是实际经过的时间，和 `duration_s` 对得上就说明没丢数据

**每按一次"开始录音"就新建一个文件**，没有按你最初说的每个词一个大文件。这样每个人、
每一轮都是单独的文件，不会因为误操作覆盖之前录的，训练时也能按说话人划分训练集和验证集
（同一个人的声音只放在一边，验证结果才可信）。Mac 那边的切片脚本会把同一个词的所有文件
一起处理，效果和一个大文件一样。

## 录音流程建议

**一个人录完一个词再换下一个人**，每人每个词单独一段，并在本子上记下
`open_003 = 小王` 这样的对应关系。

每段大约说 **100~150 遍**（间隔 2~3 秒，约 5~7 分钟），每说十几遍换一种说法：

| 维度 | 变化 |
| --- | --- |
| 音量 | 小声 / 正常 / 大声 |
| 语速 | 慢 / 正常 / 快 |
| 语调 | 平 / 上扬 / 下降 / 不耐烦 / 随意 |
| 距离 | 30cm / 1m / 2m（以后实际使用的距离一定要录到） |
| 朝向 | 正对 / 侧对板子 |

3 个人 × 2 个词 × 每人约 130 遍，大约能得到每个词 400 个样本，第一版模型够用了。

注意事项：

- **间隔里别说话**。每两遍之间的静音段，切片脚本会拿来当背景噪声样本
- 开始和结束时点屏幕的声音会被录进去，切片时掐掉首尾各 1 秒
- 背景可以有正常的家庭噪声（空调、远处的电视），反而有好处；但别在很吵的地方录全部数据

## 调麦克风增益

增益在 `idf.py menuconfig` → `KWS Recorder 配置` → `麦克风 PGA 增益`，默认 30dB（和官方出厂固件一样），
可选 0/6/12/…/42 八档。

调法：在**正常距离、正常音量**下说话，电平条峰值落在 **-20 ~ -6 dB** 最合适。
大声说时电平条变红、"削顶"计数在涨，就降一档；1m 外说话峰值还不到 -30dB，就升一档。

**正式开录之后不要再改增益**。识别固件要用同一个值；每段录音用的增益都记在 `sessions.csv` 里。

## 编译烧录

需要 ESP-IDF **6.1**（Waveshare 官方示例写的是 5.5.4，本工程在 6.1 上编译通过）。

```
source ~/.espressif/tools/activate_idf_v6.1.sh
cd ~/src/hardware/kws-recorder
idf.py build
idf.py -p /dev/cu.usbmodemXXXX flash monitor
```

TF 卡需要格式化成 **FAT32**。开机挂不上卡也能进界面，插好卡后直接点开始录音，会再试一次挂载。
挂载一直失败时，检查板子背面的 **JP8 第 2 位是否拨到 ON**（官方 BSP 的提示）。

## 实现说明

| 模块 | 说明 |
| --- | --- |
| `mic.c` | I2S0 + ES8311。板上没接 MCLK，ES8311 用 BCLK 倍频；ADC 数据在左声道 |
| `recorder.c` | 采集任务（优先级 6，每 20ms 一块）→ PSRAM 里 512KB 环形缓冲（16 秒）→ 写卡任务（优先级 4）。FAT 写卡偶尔卡几百毫秒，靠环形缓冲兜住 |
| `display.c` | ST7796，SPI 60MHz，LVGL 8 分块刷新，两块 40 行的内部 DMA 缓冲 |
| `touch.c` | FT6336，接成 LVGL 指针设备。屏做了 X 镜像之后触摸原始坐标正好对上，不用变换 |
| `sdcard.c` | TF 卡 SPI 模式，和屏共用 SPI2（SCK/MOSI 共用，靠 CS 区分） |
| `exio.c` | CH32V003 IO 扩展：屏复位、触摸复位、功放使能、背光 PWM。录音期间功放保持关闭 |
| `ui.c` | 每 100ms 刷新一次状态，只在值变化时才改控件，免得屏一直重绘、占着和 TF 卡共用的 SPI 总线 |

和 Waveshare 官方 BSP 不同的地方：

- **没用 `espressif/esp_lcd_st7796`**：1.0.0 用了 IDF 6 删掉的 `color_space` 字段，编不过；
  更新的版本 targets 里没有 esp32c5，组件管理器不让装。屏的初始化序列直接写在 `display.c` 里，
  内容和组件 1.0.0 + BSP 的后续设置完全一致
- **没用 `waveshare/custom_io_expander_ch32v003`**：它的 CMakeLists 只依赖 `driver`，
  在 IDF 6 上找不到 `driver/i2c_master.h`。协议只是往 0x24 写寄存器，直接写在 `exio.c` 里

界面字模用 `tools/gen_fonts.sh` 生成（更纱黑体，和 amoled-clock 同一份 TTF）。脚本会自动从
`ui.c` / `recorder.c` 的字符串里提取用到的汉字，改了界面文案后重跑一次即可。
