# SHTC3 读数验证

板载 SHTC3 在室温 23°C 时报 37°C，这个小程序用来判断是**软件读错**还是**板子发热**。
只开 I2C 和 IO 扩展，屏 / Wi-Fi / 音频都不初始化，背光默认关。I2C 和 IO 扩展用的是
共用组件 `../components/board`。

```
source ~/.espressif/tools/activate_idf_v6.1.sh
cd ~/src/hardware/lcd-clock/sensor-test
idf.py build
idf.py -p /dev/cu.usbmodemXXXX flash monitor
```

每 2 秒一行（示例）：

```
   12s |  23.85/45.1%  23.84/45.2%  23.90/45.0%  23.88/45.1% | T=64B8 RH=7375 | 33.92 | 片内 31.2 | VBUS=1 电池=无 待机
        正常/T先     正常/RH先    低功耗/T先   低功耗/RH先     正常/T先原始值   湿度字当温度算  ESP32-C5 片内温度  AXP2101
```

## 怎么看

1. **四种模式结果不一致** → 读法有问题（命令或字节顺序）。
2. **"湿度字当温度算"那一列接近 37°C**，而四种模式本身正常 → 之前的驱动把 RH 先出的数据当成了温度，是软件 bug。
3. **四种模式一致但都偏高** → 传感器读得没错，是它所在位置被加热了。做法：
   - 拔电放凉 10 分钟后上电，看头几行。刚上电接近 23°C、然后跟着"片内"一起往上爬，就是自热
   - `idf.py menuconfig` → `SHTC3 测试配置` → 背光改成 80 再跑一次，看背光贡献多少
   - 看最后一列：插着电池充电时 AXP2101 会发热
4. 冷启动第一行就是 37°C → 传感器本身或焊接有问题，可以拿 amoled-clock 上那颗 SHT4x 放旁边对比。
